# Daily Digest

Персональный агрегатор публичных Telegram-каналов, который помогает меньше отвлекаться: вместо постоянной ленты — один ежедневный выпуск в личном чате с ботом.

## Как работает

- Читает публичные страницы `https://t.me/s/<username>` без авторизации в пользовательском Telegram-аккаунте.
- Ежедневно в **20:30 `Europe/Moscow`** сначала очищает чат, затем собирает публикации за последние **24 часа относительно фактического времени запуска**.
- Показывает посты последовательно, блоками по каналам, без категорий, AI, пересказа или отбора по важности.
- Под каждым блоком есть кнопка **«🚫 Отписаться»**: она отключает источник в агрегаторе. Подписки основного Telegram-аккаунта пользователь меняет самостоятельно.
- Учитывает входящие сообщения владельца, команды, ответы бота и сообщения выпусков для удаления перед следующим плановым выпуском.
- Не предоставляет архив или историю выпусков. Ручной `/digest` создаёт тестовый выпуск без очистки; накопившиеся сообщения удаляются перед плановым выпуском.

«Все посты за сутки» — правило отбора доступных публикаций, а не гарантия полноты при сбоях. Веб-парсер зависит от доступности и HTML Telegram, имеет предел обхода страниц; длинный текст сокращается и сопровождается ссылкой на оригинал. Полноценное копирование всех видов медиа не заявлено.

Очистка охватывает известные боту ID сообщений. Старую неотслеживаемую историю нужно убрать вручную. Telegram обычно разрешает удаление сообщений младше 48 часов и имеет дополнительные ограничения для отдельных типов сообщений; после длительного простоя или ошибки удаления чат может очиститься не полностью. См. [ограничения deleteMessage](https://core.telegram.org/bots/api#deletemessage).

## Технологии и состояние репозитория

**VPS → Docker → Python → SQLite.** Публичные каналы читаются через HTTP и HTML-парсер; сообщения и кнопки отправляются через Telegram Bot API. Планировщик работает внутри приложения.

Добавлены повторные попытки при `TimedOut` / `NetworkError` и увеличенные таймауты Telegram API. SQLite хранит список источников и служебные ID сообщений для очистки, а не архив текстов публикаций.

На **2026-09-12** актуальные `app.py`, `Dockerfile`, `compose.yaml` и `requirements.txt` перенесены из `/opt/daily-digest` на VPS без изменений. Репозиторий содержит рабочий код, документацию и безопасный шаблон конфигурации. Привязка Git не перезапускает контейнер.

## Структура репозитория

```text
daily-digest/
├── README.md
├── .gitignore
├── .dockerignore
├── .env.example
├── app.py
├── Dockerfile
├── compose.yaml
├── requirements.txt
└── docs/
    ├── ARCHITECTURE.md
    ├── OPERATIONS.md
    └── CHANGELOG.md
```

На VPS дополнительно остаются **`.env`** и **`data/digest.sqlite3`**. Они исключены из Git, как и резервные копии, журналы и SQLite WAL/SHM. `.env.example` создан заново по проверенным ключам актуального кода: токен и ID владельца оставлены пустыми. Серверный `.env` не копировался. `.dockerignore` исключает секреты и данные из контекста сборки.

## Команды бота

Команды доступны владельцу, указанному в конфигурации.

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Справка |
| `/add <username>` | Добавить или снова включить публичный канал |
| `/list` | Показать активные каналы |
| `/remove <username>` | Отключить источник |
| `/status` | Проверить состояние, расписание и окно выпуска |
| `/digest` | Сформировать ручной выпуск без очистки чата |
