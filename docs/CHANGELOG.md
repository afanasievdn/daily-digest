# История изменений

## 2026-10-22 — Восстановление и диагностика пропавших фотографий

- Исправлено извлечение фото, если публичная страница Telegram показывает вложение через обычный `<img>` или ленивую загрузку `data-src`, а не CSS-фон.
- При обнаружении фото/видео в разметке поста, но отсутствии файла в ленте, бот дополнительно запрашивает публичную страницу конкретной публикации.
- Если фотография не загрузилась или Telegram отклонил её отправку, в дайджесте появляется «🖼 Фото недоступно», вместо молчаливой потери вложения. Текст и ссылка остаются.
- Добавлены регрессионные тесты. Исправления в GitHub требуют **отдельного развёртывания на VPS**. Оно не производится при коммите.
- Гарантия доставки каждого вложения невозможна через публичную HTML-страницу; пользовательский Telegram-клиент не используется.

## 2026-10-20 — Надёжный ежедневный запуск

- Планировщику задан допуск в 5 минут: небольшая задержка запуска больше не отменяет выпуск.
- Исправление основано на журнале от 20 октября: прежний запуск был пропущен из-за задержки 6 секунд.

## 2026-10-19 — Открытие изображений на мобильных устройствах

- Для текста публикации всегда отключено автоматическое превью ссылки Telegram.
- Доступные фотографии и альбомы по-прежнему отправляются отдельными вложениями и открываются во встроенном просмотрщике.
- Переход в исходный канал остаётся только по явной ссылке «Открыть пост». Если вложение недоступно, ложная кликабельная картинка не показывается.

## 2026-10-09 — Поддержка фотографий и видео в дайджесте

- Добавлен `media_support.py`: парсер изображений и видео из публичных страниц Telegram; фотографии отправляются как файлы, альбомы — группами.
- Видео отправляется при наличии доступного источника, иначе может использоваться миниатюра.
- Недоступные и слишком большие медиа пропускаются, при этом текст и ссылка на исходный пост остаются.
- ID сообщений с вложениями сохраняются для следующей плановой очистки.
- Dockerfile дополнен новым модулем. Добавлены синтетические тесты разбора и отправки.
- **Изменения закоммичены в GitHub; развертывание на VPS и проверка на живых каналах ещё не выполнены.**

## 2026-09-12 — Перенос текущего кода с VPS

- Без изменений перенесены `app.py`, `Dockerfile`, `compose.yaml` и `requirements.txt` из `/opt/daily-digest`.
- Проверено отсутствие характерных токенов и приватных ключей; вручную просмотрено содержимое исходников. `.env` и база не читались и не копировались.
- Добавлен новый `.env.example` по ключам реального кода, с пустыми токеном и ID владельца.
- Добавлен `.dockerignore`, исключающий окружение, данные, Git и резервные копии из контекста сборки.
- Документация сверена с кодом; перечислены реальные ключи конфигурации, ограничения медиа и повторный учёт старых ID при инициализации.
- Логика работающего приложения этим переносом не меняется; контейнер не пересобирается.

## 2026-09-12 — Документация репозитория

- Добавлены README, описание архитектуры, руководство эксплуатации и инструкция безопасной привязки VPS к GitHub.
- Добавлен `.gitignore`: исключены `.env`, локальные варианты окружения, `data/`, SQLite и её вспомогательные файлы, секреты, резервные копии и журналы.
- Зафиксированы расписание 20:30 `Europe/Moscow`, окно последних 24 часов, блоки по каналам, отключение источников кнопкой и отсутствие архива.
- Актуальные файлы приложения остаются на VPS до отдельного переноса по инструкции. Проверенный `.env.example` можно добавить после сверки с реальным кодом; значения окружения с VPS не копировались.

## 2026-09-12 — Доработки приложения на VPS

Записано по предыдущему обсуждению и результатам, сообщённым владельцем; это не новые изменения кода в данном коммите.

- Добавлены до 4 попыток отправки сообщений выпуска при `TimedOut` / `NetworkError`.
- Увеличены таймауты Bot API: connect/pool — 30 секунд, read/write — 60 секунд.
- Владелец подтвердил получение блока `@Nackepelo` после доработки отправки.
- Добавлена таблица `chat_messages` и учёт входящих сообщений владельца и исходящих сообщений бота.
- Полная очистка отслеживаемого чата перенесена в начало планового выпуска; ручной `/digest` выполняется без очистки.
- Добавлены повторные попытки удаления при временных сетевых ошибках.
- Ручная проверка показала `TRACKED: 0`; владелец подтвердил, что сообщения в Telegram исчезли. Автоматический вечерний запуск этим ручным тестом не подтверждается.

## Предшествующее состояние

- Python-приложение работает в Docker на VPS, состояние хранится в SQLite.
- Публичные каналы читаются через `t.me/s/<username>`.
- Реализованы команды владельца, ежедневный выпуск и inline-кнопка отключения источника.

Точные даты первоначальной реализации и версии зависимостей здесь не назначаются: их нужно уточнить по актуальному коду и дальнейшей истории Git.
